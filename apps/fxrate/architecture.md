# FxRate 아키텍처

## 모듈 구성

앱 모듈은 조립만 둔다(진입점, 내비게이션, 딥링크, 포트 바인딩). 환율 도메인은 이 앱 전용이라 shared 가 아니라 앱 하위 모듈에 둔다.

```
:apps:fxrate
├── core:common    환산·환율판·변동 판정·입력 파싱·통화 카탈로그·표기·소스 계약 (Android 비의존)
├── core:database  Room(캐시·즐겨찾기·알림 규칙) + 기준 통화 DataStore
├── core:widget    Glance 위젯, 리시버·리소스 소유
├── feature:rates     환율 탭
├── feature:alerts    알림 탭
├── feature:settings  설정 탭
└── feature:splash    강제 업데이트 게이트
```

feature 모듈끼리는 의존하지 않는다. 화면 사이 이동(예: 환율 화면의 알림 버튼 → 알림 탭에 통화쌍 전달)은 콜백과 효과로 올라와 앱 모듈이 처리한다. 위젯이 core 모듈이라 공유 로직을 화면 모듈에 두면 core 가 feature 를 의존하게 되므로, 공유 로직은 `core:common` 에 둔다.

## 데이터 흐름

```
서버 스케줄 → 외부 환율 API → Firestore fx_rates/USD → (앱) 캐시 저장 → 화면·위젯
```

- 화면과 위젯은 값을 Room 캐시에서만 읽는다
- 앱이 외부 API 를 직접 부르지 않는 이유는 호출량이다. 호출이 사용자 수에 비례하면 소스의 월 무료 쿼터를 금방 넘고, 서버 한 곳이 폴링하면 사용자가 늘어도 호출량이 그대로다
- 현재 구독은 배선되지 않았다. 캐시를 채우는 것은 debug 의 개발용 시드(`DevSeeder`)뿐이다

## 핵심 설계

### 환산 (core:common)
- `CrossRateCalculator` 는 `1 X = N Q` 한 방향만 다룬다. 방향을 표현할 수단이 하나뿐인 API 모양으로 반대 방향 오류를 막는다. 테스트가 한 방향으로 일관되면 통과해 버리므로 규율이 아니라 형태로 막는 것이다
- 원본 기준 통화는 인자로 받는다. 함수 안에 통화를 박으면 서버가 기준을 바꿀 때 조용히 틀린 값을 낸다
- 이 모듈이 틀리면 예외 없이 숫자만 조용히 틀리므로 JVM 유닛 테스트로 검증 가능해야 한다. 그래서 Android·Compose 의존을 늘리지 않는다. 변동 색 `TrendPalette` 를 `Color` 가 아닌 ARGB `Long` 으로 둔 것도 이 때문이다(화면 `Color` 와 위젯 `ColorProvider` 는 공통 상위 타입이 없다)
- 서식은 기기 로캘에 기대지 않는다. 기호는 `Locale.KOREA` 고정
- `RateBoard` 가 화면과 위젯의 환산·변동량·줄 고르기를 하나로 맡고, 둘의 차이(기본 목록·최대 줄 수)는 인자로 받는다

### 저장소 (core:database)
- 테이블 4개: `favorite_currencies`, `rates`, `rate_meta`, `alert_rules`. 캐시와 사용자 데이터를 한 DB 에 둔다. 나누면 Room 인스턴스가 둘이 되는 비용 대비 이득이 없고, 대가로 파괴적 마이그레이션을 쓸 수 없다
- 변동 화살표용 직전 값을 별도 이력 테이블 대신 같은 행의 `previousValue` 에 둔다. 값이 달라졌을 때만 옮긴다. 15분 주기 소스는 값이 안 바뀌는 구간이 흔해서, 매번 옮기면 같은 값이 한 번만 더 와도 변동이 0 이 돼 화살표가 사라진다
- 빈 스냅샷은 캐시를 지우지 않는다. 소스 장애 때 오프라인 화면이 비는 것을 막는다
- 시각을 `quoteAt`(소스가 밝힌 기준 시각)과 `fetchedAt`(받은 시각)으로 나눈다. 하나만 두면 사용자에게 실제보다 신선해 보인다. 갱신 주기(`granularity`)도 서버가 쓰는 소스에 따라 바뀌므로 저장한다
- `armed`(알림 재발동 준비 상태)는 서버가 소유한다. 저장소가 바꾸지 않는다

### 앱 조립
- 시작 목적지는 스플래시이고, 홈 이동이 알려지면 환율 탭으로 가면서 스플래시를 백스택에서 지운다. 탭은 환율 → 알림 → 설정
- 딥링크는 `HOST_TO_ROUTE` 맵 하나에서 화이트리스트와 라우터를 파생한다 (`rates`·`alerts`·`settings` host). 검증은 공용 디스패처가 하고 라우터는 매핑만 한다
- 위젯은 `MainActivity` 를 직접 참조하지 않고 `AppLaunchInfo` 포트를 EntryPoint 로 받는다. 직접 참조하면 core 가 앱을 거꾸로 의존한다
- `DevSeeder` 바인딩은 소스셋으로 갈려 목 데이터 코드가 release 소스셋에 아예 없다. 스토어 빌드에 섞일 수 없다

## 서버 중계 계획 (미구현)

- **스키마**: `fx_rates/{base}` 문서 하나에 전 통화를 담는다(통화별 문서는 리스너 N개로 read 가 N배). `fx_history` 는 차트용, `fx_alerts` 는 알림 규칙
- **폴링**: 소스 쿼터가 주기를 정한다. 무료 티어 월 1,000회 기준으로 1분·24시간(월 43,200회)은 불가하고, 평일 08~24시 30분 간격(월 704회)을 채택안으로 잡았다. 외환시장이 주 5일이라 주말은 손실이 없다
- **알림 평가**: 서버가 한다. 앱이 평가하면 앱이 꺼져 있을 때 알림이 가지 않는다. 임계값 근처 진동으로 알림이 폭주하지 않도록 `armed` 히스테리시스(0.3% 재무장 여유)를 건다. FCM 은 data-only 로 보내고 탭하면 딥링크로 들어온다
- **리스너**: 화면이 보이는 동안만 부착한다. 상시 부착이면 무료 read 한도를 사용자 35명이 소진한다
- 클라이언트의 직접 쓰기를 막고 callable Function 으로만 규칙을 조작하게 한다. 로그인은 요구하지 않는다(FCM 토큰으로 익명 식별)
- **소스**: 주 소스는 기준 시각을 주고 과거 데이터가 무료인 서비스(FXRatesAPI)로, 폴백은 CC0 라이선스 공개 데이터로 정했다. 상업 이용이 막힌 소스와 갱신이 느린 소스는 탈락시켰다. 서버 중계가 재배포에 해당하는지 약관 확인이 출시 전 과제로 남아 있다
